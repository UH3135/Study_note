### ✅ 500 에러 해결을 위한 단계

이전과 동일하게 Gunicorn 로그를 확인하여 `Traceback`(에러 추적 메시지)을 찾는 것이 핵심입니다.

#### 1단계: Gunicorn 로그 실시간으로 확인하기 (가장 확실한 방법)

1. 서버에 SSH로 접속한 터미널에 아래 명령어를 입력합니다.
    
    Bash
    
    ```
    sudo journalctl -u gunicorn -f
    ```
    
    이 명령어는 Gunicorn의 로그를 실시간으로 보여줍니다.
    
2. 이 터미널 창을 그대로 열어둔 채로, 웹 브라우저에서 500 에러가 발생하는 페이지를 **새로고침**합니다.
    
3. 새로고침하는 순간, 터미널 창에 새로운 로그와 함께 **Python `Traceback` 에러 메시지**가 나타날 것입니다.
    

#### 2단계: Traceback (에러 메시지) 분석하기

터미널에 나타난 `Traceback` 메시지가 에러의 원인과 위치를 알려주는 결정적인 단서입니다.

- `Traceback`의 **맨 마지막 줄**이 어떤 종류의 에러인지 알려줍니다.
- `Traceback`에서 **내 프로젝트 파일 경로**가 언급된 부분을 찾아, 어떤 파일의 몇 번째 줄에서 문제가 발생했는지 확인합니다.

#### 3단계: 코드 수정 및 Gunicorn 재시작

1. `Traceback`에서 확인한 파일과 라인 번호를 찾아 `nano` 등의 에디터로 코드를 엽니다.
2. 에러의 원인을 찾아 코드를 수정한 뒤 저장합니다.
3. **수정된 코드를 적용하려면 반드시 Gunicorn을 재시작해야 합니다.**
    
    Bash
    
    ```
    sudo systemctl restart gunicorn
    ```
    
4. Gunicorn 재시작 후, 다시 웹 브라우저에서 페이지를 새로고침하여 에러가 해결되었는지 확인합니다.

만약 또 다른 500 에러가 발생한다면, 또 다른 버그가 드러난 것이므로 위 1~3단계를 반복하여 해결해 나가시면 됩니다.
