## AI

1. **Langchain과 Langgraph를 선택한 이유 및 장점**
    
    - 풍부한 자료와 커뮤니티 지원, 다양한 플러그인과 템플릿 제공으로 빠른 프로토타이핑과 유지보수가 용이함.
        
    - 다른 LLM 프레임워크 대비 문서화가 잘 되어 있고, 실무 적용 사례가 많아 문제 해결이 빠름.
        
2. **RAG(Retrieval-Augmented Generation) 시스템의 핵심 구성 요소와 역할**
    
    - 텍스트 스플리터: 문서를 적절한 크기로 분할해 검색 효율성 향상.
        
    - 임베딩 모델: 텍스트를 벡터로 변환하여 의미적 유사성 계산.
        
    - 벡터 DB: 벡터 형태로 저장된 데이터의 빠른 검색 지원.
        
    - 리트리버: 쿼리와 유사한 벡터를 DB에서 찾아 반환.
        
    - LLM: 리트리버가 반환한 정보를 바탕으로 응답 생성.
        
3. **임베딩 모델 성능 평가 기준 및 최적 모델 선택 방법**
    
    - Faithfulness(정확성), Relevancy(적합성) 등으로 평가.
        
    - 벤치마크 데이터셋을 활용해 다양한 모델을 비교 실험 후, 프로젝트 목적에 가장 부합하는 모델을 선택.
        
4. **벡터 데이터베이스와 전통적 관계형 데이터베이스 차이점**
    
    - 벡터 DB: 임베딩 벡터 기반, 의미적 유사성 검색에 최적화.
        
    - 관계형 DB: 테이블 기반, 명확한 스키마와 정형 데이터 처리에 강점.
        
5. **PyTorch와 Scikit-learn 사용 상황**
    
    - PyTorch: 최신 딥러닝 모델 개발 및 커스텀 학습이 필요한 경우.
        
    - Scikit-learn: 전통적인 머신러닝 알고리즘 및 빠른 프로토타이핑에 적합.

## 백엔드 기술

6. **Django vs FastAPI 차이점 및 적합 상황**
    

|구분|Django|FastAPI|
|---|---|---|
|특징|풀스택, ORM 내장|경량, 비동기 지원|
|적합 상황|대규모/기업용|소규모/스타트업, API|

7. **Django ORM vs Raw SQL 쿼리 장단점**
    
    - Django ORM: 유지보수 용이, 코드 일관성, 보안성 높음. 복잡한 쿼리엔 한계.
        
    - Raw SQL: 성능 최적화 가능, 복잡한 쿼리 지원. 유지보수 어렵고 오류 위험.
        
8. **RESTful API 설계 원칙 및 적용 사례**
    
    - 클라이언트-서버 분리, 무상태성, 계층화, 일관된 URI 설계 등.
        
    - 실제로 Streamlit-Backend(Flask/FastAPI) 구조에서 API 명확히 분리 적용.
        
9. **비동기 처리 필요 상황 및 구현 방식**
    
    - 파일 저장/로드, 대용량 데이터 처리 등에서 필요.
        
    - Python의 asyncio, FastAPI의 비동기 엔드포인트, Celery 등 활용.
        
10. **데이터베이스 성능 최적화 방법**
    
    - 인덱스 최적화, 쿼리 튜닝, 캐싱, 정규화/비정규화 전략 병행.
