## Probability and Information
### 확률
- Joint 확률
	- 입력이 여러개인 확률
- Marginal probability
	- 원래 여러개를 보는 확률인데 밀어서 하나를 줄여서 보자
- Conditional probability
	- Joint 확률을 marginal 확률로 나눔
### 확률 밀도 함수
- histogram에서 나오는 결과
- 특정 구간으로 생각
- y값은 likelihood임 -> 여기서 뽑히면 이정도의 확률일 거 같다
### Expectation
- 확률 함수를 뽑고 일단 돌려보고 나온 값을 생각하는게 기댓값
- 많이 뽑히면 가중치가 크고, 적게 뽑히면 적게
- 데이터셋을 모은다 = 뽑힌 데이터를 가져온것
	- 즉, 이미 데이터셋에 적용되어 있음
## Information Theory
- 일어나지 않을 일은 높은 가치, 항상 일어나는 일은 낮은 가치가 있다
- $I(x) = -log{P(x)}$ 
- $I(x)$ 기댓값 = 엔트로피$H(x)$
- 딥러닝에서 다루는 이유?
	- kullback-leibler를 다루기 위해
	- $D_{kl}$은 Q와 P의 차이를 아는 방법
	- 분포를 배우기 위해
	- 항상 나오지는 않고 확률적으로 튀어나옴
	- 예시)
		- P와 Q라는 분포가 존재
		- 얼마나 다른지를 측정
		- **샘플을 P에서 뽑아서**
		- $𝔼_{x-p}[log{P(x)}/{Q(x)}]$ 이렇게 계산했을때 차이가 있을것 -> 이에 집중하면 같거나 다름을 알수있음
		- $H(P,Q) = -𝔼_{x-p}[\log{Q(x)}]$  (크로스 엔트로피)
		- $H(P,Q) = H(P) + D_{KL}(P||Q)$ 
			- 둘의 차이는 크로스 엔트로피를 구하면 되네?
		- P는 뭐고 Q는 뭔데?
			- P는 데이터셋
			- Q는 AI가 생성한 예측값
## Capacity, Overfitting, and Underfitting
- iid condition
	- 트레이닝과 test를 분류하는 이유는 Train data에 과하게 학습되지 않았는지 분별
	- Traing data와 test는 서로 유사한 데이터이어야한다
- capacity
	- 모델을 복잡하게 만들것인가?
	- 높으면 overfitting, 낮으면 underfitting
	- 즉, 너무 높을 수록 학습데이터만 잘 설명하고
	- 낮으면 너무 동떨어진 답을 이야기한다
- 심플하게 설명할 수 있으면 정답이다
- Regularization
	- overfitting이 안일어나게 할것인가?
	- 사람이 학습에 개입
	- $MSE_{train} + λw^T w$
		- $w$: 인간의 개입
		- capacity를 엄청나게 잡는다
		- 이 다음 모델의 차수를 결정 -> 각 계수를 가중치로 설정
		- 선호도를 넣는것 -> 가중치의 값을 아래로 눌러주는것
	- **맞추는 것 중에서 가장 심플한게 좋다**
### Hyperparameters
- λw^T를 얼마나 잘 결정할 것인가
- validation set -> 수능 특강: 훈련할 때 안보다가 확인해서 스스로의 성취를 확인하는 것
	- 8:2 정도의 비율
	- 트레인 할 때마다 validation을 변경 -> k-fold cross-validation
- 모든 것은 인간의 학습에 적용해보면 이해가 쉬움
## Maximum Likelihood Estimation
- 가능성을 최대로?
- 생성모델을 만들때 상황?
	- 모든 사람을 찍는다고 해도 새로운 사람을 만들기는 어렵다
	- 하지만 가능하다고 가정하고 랜덤한 샘플을 찍는다
		- 다만 독립적으로 찍는다
- $x;θ$에 의해 결정 -> 이 θ를 모델 파라미터라고 칭함
	- 우리가 뽑은 값이 정규 분포를 따를 것이라고 생각함
	- 그 값을 나오게하는 평균과 분산에 관심이 있다
- 어떤 모델을 설정했다 -> 정규분포를 통해서
- 결정의 근거는 theta를 통해 -> 평균과 분산을 결정
- likelihood의 곱이 가장 잘 나왔을때로 결정
- model이 전부 NN로 변경!

HWP TO JSON 코드의 방법
1) 연구 배경 및 문제 정의
- HWP 문서를 JSON으로 변환하는 과정에서 **표(Table), 이미지(Image), 수식(Equation) 처리의 어려움**과 **전체적인 실행 시간 증가** 문제가 발생함.
2) 기존 방식 검토 및 실험
- HWP → JSON 직접 변환:
    - 변환 과정에서 복잡한 요소(표, 이미지, 수식 등) 처리가 어렵고 실행 시간이 길어지는 단점이 있음.
- HWP → PDF → JSON 변환:
    - JSON 변환을 위한 다양한 자료와 시도가 존재하여 먼저 검토.
    - 그러나 문서의 순서 저장이 어려운 문제가 있음.
    - 특히, **이미지나 표가 있는 경우** 텍스트 중간에 표나 이미지가 삽입되는 치명적인 문제 발생.
1) 해결 방안 모색
- HWP를 여러 형식으로 변환한 후, 문서 형태가 원본과 얼마나 유사한지 비교하는 실험을 진행함.
- 기존 변환 방식의 한계를 분석하여, 보다 효율적인 변환 방식을 탐색 중.
