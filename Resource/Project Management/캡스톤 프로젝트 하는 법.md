#### 회사는 여러분이 만드는 것에 관심이 없다
- 기업이 만드는 거랑 다르기 때문에
- 그러면 관심있는거는?
	- 어떻게 만들었니?
	- 모르는 부분은 어떻게 해결했니?
	- 예시
		- 백엔드에 어떤 프레임워크를 썼는데 만약 이 프레임워크가 없으면 어떻게 할거니?
#### 현재 취업시장은 많이 얼어있다
- 게임, 스타트업 모두 구조조정을 진행 -> 시장에 3, 4년차 개발자들이 많음
- 스타트업 투자도 별로 없음
- AI가 시니어 개발자의 생산력을 늘리고 있음 -> 신입이 필요한가?
- 인턴, 신입에도 경력직을 요구함
- 공채 또한 없어지는 추세
- 100명 중에 한명 뽑는 정도
- 3, 4년 전이랑 다른 거는 없다 -> 회사는 가능하면 경력직으로 뽑는다
#### 경력직 신입을 요구하지 않을때
- 추가로 보유하고 있다면 좋은 스킬셋 -> 굉장히 중요한 부분, 당연히 만족해야 한다
- 인턴에 도전 : 이름을 처음 들어본 회사들
	- 모든 산업 -> 바이오, 관광, 제조 등등
### 소프트웨어 개발자의 역량 성장
- 언어, 자료구조
	- 과제를 통해 열심히 배운다
- framework
	- 결과를 보면서 즐겁게 배운다
- 알고리즘
	- 회사에서 실제로 많이 사용하지 않는다 -> 심각하게 생각하지 않음
	- 코딩 테스트라는 벽이 존재
	- 알고리즘이 중요하면 코드를 단순하게 작성
	- 전략적으로 공부해야 한다
- CS core
	- 레벨을 올리기 위한 방법
	- 이게 왜 문제인지도 모르고 맞추었다 -> 지식을 책으로만 습득
	- 실제 문제가 발생했을때 직접 책을 보고 해결해야 한다
- Domain 경험
	- 직장에 들어가서 직접 경험하면서 성장
#### 옆에 있는 사람은 그저 조금 먼저 배운 것뿐이다
- 진짜 천재는 거의 만나지 못한다 -> 만나면 친하게 지내세요
#### 학습은 어떻게 해야하는가
- 직접 경험해보고 문제가 생기면 책을 확인하자
- 여러가지를 많이 배우고 해야한다
- 주제를 깊이있게 이해하는 것이 매우 중요하다
- 문제를 팀 안에서 공유하는 것이 중요
### 프로젝트 기반 학습
- Learning이 키워드
- 뭘 만드는 지가 중요한게 아니라 뭘 **배웠는지**가 중요하다
- 하나를 하더라도 깊이있게 공부해라
- 상금이 있는 상이 더 중요하다
### 문제
- 문제를 이해하고 어떻게 해결할까에 대해서 고민하자
- 시작하는 것이 문제가 아니다
- 이 문제를 해결했을때 당연하게 얻은 지식이 있는지 확인하는것
- 따라하지 않고 만든 것
- 따라하더라도 만들었을때 반드시 알고 있는 것
- 평가
	- 예외는 잘 처리되었는지
	- 문제에 대한 답이 논리적으로 시간적으로 잘 나오는지
	- 코드는 가독성이 좋은지
	- 지식을 잘 습득하였는지
## 성장이란
- 새로운 제품을 만드는 역량을 습득
	- 사용자의 요구를 수용하며
	- 운영상의 문제 해결
	- 시장 상황, 기술의 변화에 따라 가는것
### 재미
- 결과가 나왔을때만 재밌다 -> 과정은 재미없다
- 아무리 작아도 결과가 나오면 흥미롭고 열정이 생긴다
- 다음 목표를 잡는 것이 핵심
- 재미가 없으면 타깃을 빠르게 바꿔라
- 일을 엄청 잘게 쪼개서 점진적으로 진행해라
### 협업
- 조종 능력, 소통 != 협업이 아니다
- 한명이 회사를 그만두어도 유지되는거? == 모든 사람이 전체를 할 줄 알아야 함
- 협업: 그 일을 어떻게 했는지
- 네트워크: 뭘 잘하는지, 태도는 어떤지, 어떤 생각의 틀을 가졌는지
- 결국 코드를 보는것 == 코드 리뷰를 진행해야 한다
- 남이 보낸 풀리퀘에 어떻게 리뷰를 하였는지
- 영역이 다르더라도 조금이라도 봐야한다
- 조금이라도 서로 코드를 가지고 읽어보는 시간이 필요하다
- 회고를 진행해라
#### 현장을 넘는 배움터는 없다
- 학교는 인덱싱을 잘해준다
- 스스로 진행하고 도전하라
### 너가 필요해서 만든거는 있니?
깃허브를 슬랙에 연동하여 PR을 확인할 수 있게

- 이후 작은 기능 단위로 추가 후 배포
	- 점진적으로 개발해서 보여드리는 것
### 운영경험
- 진짜 사람을 조기에 확보
- 가짜 고객 만들기 서버에 접근하는 CLI 버전의 가짜 Client를 많이 생성 -> 서버에 stress를 주고 traffic, 동시성을 확인한다
- 언제나 멋진 데모를 준비
- 로그나 모니터링을 할 방법을 찾아 측정 후 개선
